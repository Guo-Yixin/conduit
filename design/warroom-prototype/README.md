# War Room prototype (v0 export — trace waterfall)

**Status: design reference, not production code.** This is the v0.dev-generated
prototype that validated the War Room's **trace-waterfall paradigm**, TUI visual
language, and time-axis-as-andon behavior. It serves
[`prd/drafts/war-room.md`](../../prd/drafts/war-room.md) as the visual spec — the real
implementation is scaffolded *from* it (via `/ai-team:plan` once the PRD is ready),
never evolved *in place* here.

## Paradigm history (why the components changed wholesale)

The first prototype round was a kanban-style **station board** (collapsed station
slivers, terminal rail, child sub-path band). It iterated well but **failed the
narration test** — even the system's author could not read a run's story off it. The
second round rebuilt around a **trace waterfall** (one row per card, time on x, one
colored segment per station visit) and passed the narration test immediately. The PRD
records the decision (§8, §10); the board survives only as a candidate future secondary
view for high-WIP flows.

`screenshots/` currently holds **board-era captures** — kept as the record of the
failed paradigm the PRD cites. Waterfall captures can be regenerated by running the
prototype (the mock scenario is self-driving, including the budget-wall approach and
replay mode).

## Running it

```bash
bun install && bun run dev
```

## What this prototype validated (recorded in the PRD)

- The waterfall's five legible shapes: fan-out fork, rework zigzag, scrap death,
  held/OVERDUE bar, fan-in convergence — PRD §8
- Time axis = consumption andon: fit-all compression, min segment width, the red wall
  line entering at ~70% of wall budget, drag-zoom + transient minimap — PRD §8
- Strict replay rollback: header meters/tallies/watchdog all derive from the scrubbed
  event prefix, never the live head — PRD §8
- Terminal/TUI visual language; station-identity colors on segments with state as
  markers; deliver is teal to avoid the green now-line collision — PRD §7, §9
- Live-default footer with modal replay — PRD §8

## Keep / strip map for the real implementation

The real War Room is a static SPA bundled by Bun and served from the kernel binary by a
`conduit watch` command, with data over one-directional SSE (PRD §9). Translating:

**Keep:**

- `components/warroom/*` — the component tree and Tailwind classes
  (`timeline-waterfall.tsx` is the core; `tui-panel.tsx` is the bordered-panel chrome).
  Components should stay pure functions of projected state.
- **`lib/warroom-data.ts` — the projection sketch.** `projectRows(events, nowSec)` and
  the header-stats fold are pure functions over a journal-event slice; this is the
  reference shape for the real shared `project` reducer. The `JournalEvent` /
  `Status` / `Station` types are close to the kernel's — reconcile against
  `src/types/kernel.ts` and the card log rather than reinventing.
- `hooks/use-warroom.ts` — the live/replay mode logic (both modes slice the same
  journal and feed the same projection; keep that property at all costs).

**Strip:**

- Next.js scaffolding (`app/`, `next.config.mjs`, `next` dep, `pnpm-lock.yaml`) —
  collapses to one `index.html` + entry for `bun build`.
- The mock `JOURNAL` array and its self-driving timer — the SSE stream + snapshot
  endpoint replace them (reactiveSWR, single-cache-key reducer shape — PRD §9).
- `"use client"` directives, any `@vercel/*` deps.
- Any component-owned fetch/state beyond the projection — per the PRD §7 stop rule.

**Verify against the PRD before scaffolding work items:**

- Replay rolls back *all* header elements (PRD §8 strict-rollback rule).
- OVERDUE blink on held cards past timeout; minimap appears only when zoomed.
- Status chips use kernel status names only (waiting/ready/claimed/working/
  done_pending_ack/held/awaiting_children/complete/scrapped).
- "— no events yet —" (empty prefix) is distinct from "· not recorded ·" (journal gap,
  FR-13).
