## Summary

A clean, successful mission: all 9 work items (WI-413 → WI-421) shipped in commit `9ea2052`, full suite green at **1043/1043** with a clean typecheck. The pipeline did its job — every rejection was a real defect caught before merge (a `Bun.inspect` byte leak, a path-traversal hole, a null-crash, an over-broad error classifier, and one integration-wiring miss Stockwell caught). The single most significant *process* finding is the WI-421 AC4 false-positive cycle: a keyword classifier took **two full rework loops** to converge on a correct regex, signaling that "match the error message" ACs need adversarial example sets up front. A secondary operational finding is a **dispatch/heartbeat pool race** that spawned a duplicate Amy. Top recommendation: when an AC hinges on string/pattern matching, require the work item to ship with explicit positive **and** negative match fixtures so the maker converges in one pass.

## Rejection Patterns

Four rework-triggering events across three items (6 of 9 items ran clean first-pass):

- **WI-413 — ModelCall seam + image-loading utility** (rej=1): Rejected by **Amy** — two issues: (1) CRITICAL NFR-3 byte leak — `Bun.inspect(img)` / `console.log(img)` revealed raw image bytes because `[Bun.inspect.custom]` was missing; (2) path traversal in `loadImageInput` (no `projectRoot` bounds check). Both fixed; re-approved 17/17.
- **WI-414 — declare image inputs in flow.yaml** (rej=1): Rejected by **Amy** — advisory null-crash: a non-list `image_inputs` field crashed `collectErrors` instead of being cleanly rejected. Fixed with an `Array.isArray` guard before the `for...of`.
- **WI-421 — classify image-to-text-only-model rejection as non-retryable** (rej=2): Rejected by **Amy twice**. First FLAG: `msg.includes('image') || msg.includes(...)` matched far too broadly (`image_quality`, `image-too-large`, `image-format` all false-positived AC4). First rework's "concept-level regex" still leaked. Second rework landed a two-anchor regex `/does not support image inputs?|vision is not (?:available|supported)/i`. Three maker attempts total.

**Pattern:** Every rejection was a **boundary / hostile-input defect that unit tests written to the happy path did not cover** — observability leakage (inspect), filesystem boundary (traversal), malformed config shape (non-list), and adversarial error-string matching (over-broad classifier). None were logic errors in the core feature; all were edge/abuse surfaces. WI-421 specifically shows the cost of a *match-the-text* acceptance criterion without a fixed adversarial corpus: each rework only patched the examples Amy named, so the next-broadest false positive survived to the following round.

**Recommendation:** For any AC of the form "classify/match/detect based on a string or pattern," the work item must ship with an explicit table of **must-match** and **must-NOT-match** strings, and Murdock must encode the full table as a parametrized test before B.A. writes the matcher. This converts "tighten until Amy stops finding holes" (N rounds) into "satisfy the pinned corpus" (1 round). Add the negative-corpus expectation to the `work-breakdown` AC standard.

## Investigation Findings (Amy)

Amy probed all 9 items. 6 returned VERIFIED-clean on first investigation; 3 produced actionable FLAGs (detailed above). Highlights of what manual probing caught that tests missed:

- **WI-413**: Raw bytes leaking through Bun's default inspector — a real data-exposure surface invisible to functional tests.
- **WI-413**: Path traversal in `loadImageInput` — declared path escaping `projectRoot`.
- **WI-414**: Null/non-list config field crashing the loader instead of producing a clean validation error.
- **WI-421**: Over-broad error classifier (two rounds) — false-positive scrap classification on unrelated `image*` error messages.

**Pattern:** Amy's value concentrated in three probe categories — **observability/data-leak** (inspect output), **filesystem boundary** (traversal), and **adversarial string-matching** (classifier). These are exactly the surfaces a maker writing to ACs tends to under-test.

**Recommendation:** Murdock should add standing test obligations for transform stations that handle external bytes/paths: (1) a "no raw payload in inspect/log output" assertion whenever a type carries large binary fields; (2) a path-escape rejection test whenever a utility resolves a caller-supplied path under a root; (3) a negative-match corpus whenever an AC classifies on message text. The `security-input` and `test-writing` skills should cross-reference these three obligations.

## Final Review Issues (Stockwell)

- **WI-416 — image-input placeholder rejection in renderPrompt**: FINAL REJECTED. `renderPrompt` had been widened to a 5th `imageInputs` argument, but the **executor never passed it** — the new arg was dead at the only production call site. One-line executor fix, then re-approved.

**Pattern:** A classic **integration-wiring gap**: the unit under test (WI-416) was correct and fully covered in isolation, and its consumer wiring lived in a *different* item (WI-419 executor wiring). Each item's tests passed; the seam between them was untested until Stockwell's cross-cutting pass. This is precisely the gap class the `perspective-test` skill (wiring trace) exists to catch.

**Recommendation:** When a contract change widens a function signature that a *later* work item is responsible for calling, the item that widens the signature should include a wiring-assertion test (or an explicit note that the caller is wired in WI-XXX) so the new parameter cannot ship dead. Lynch should treat "new optional parameter with zero production call sites in this diff" as a flag, not an approval.

## Pipeline Observations

- **WI-421 cycled work → check → rework twice** (murdock-2 → ba-1 → lynch → amy → repeat ×2). The instability was confined to one item and one AC; the rest of the line was stable. The back-edge worked exactly as designed — the concern is round-count, not correctness.
- **Heartbeat / pool race condition (operational):** During a heartbeat, Hannibal mis-identified amy-2's live pool slot as orphaned, racing against lynch-2's peer handoff and the heartbeat pool-cleanup. A duplicate Amy (`amy-1-2`) was spawned and then resolved via `shutdown_request`. No work was lost or duplicated in the artifact record, but this is a real concurrency bug in pool lifecycle management: a peer-handoff-in-flight slot looks identical to an orphaned slot to the cleanup pass.
- The remaining 6 items flowed straight through (murdock → ba → lynch → amy → verified) with no congestion.
